Security Practices

Security designed for high-trust messaging.

ZeusChat combines verified identity, session controls, disappearing content, CSRF protections, and escrow-backed commerce to reduce abuse without sacrificing anonymity.

Report a security issue Read safety policy

Identity controls

Zeus-PIN identity decouples messaging from phone numbers while admin approval and KYC checks reduce bots, impersonation, and mass-abuse accounts.

Message controls

Delivery state, seen state, delete-everywhere flows, and TTL expiration keep message lifecycle behavior explicit and testable.

Session protections

CSRF validation, protected mutating endpoints, unlock gating, and secure session cookies help defend the browser surface.

Encryption and privacy posture

  • Private account identity based on Zeus-PIN instead of public phone numbers.
  • Message lifecycles designed around limited retention and user control.
  • Admin moderation paths to remove abuse and handle disputes.
  • Low-bandwidth optimizations so privacy features still work under constrained networks.

Operational practices

  • Regression tests cover auth, admin, Ghost Market, Ghost Community, PIN expiry, and circuit breakers.
  • Feature verification endpoints exist for system smoke validation before releases.
  • Escrow and creator-payment logic use tracked state transitions rather than hidden side effects.
  • Security reports can be sent to security@zeustechafrica.com.
